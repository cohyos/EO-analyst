# UI-MOBILE-iphone — iPhone readability audit

## 1. Method

- **Complaint under investigation**: "יש המון מקומות שלא ניתן לקרוא את הכותרות או את העיקר של המידע שנאסף" — headings/core collected info unreadable on iPhone over Tailscale.
- **Date**: 2026-09-15. **Commit**: `4a61253`.
- **Devices**: `iPhone 14` (WebKit/Safari — what the user actually sees) and a Chromium cross-check at 390×844, `isMobile:true, hasTouch:true` (project `mobile-390x844`, already defined in `e2e/playwright.config.ts`).
- **Themes**: light and dark, both captured (via the app's own `eo-analyst-ui` localStorage persist key, matching `screens-tablet.spec.ts`'s approach). Dark theme reproduces every defect below identically (same DOM/CSS, only colors change) — confirmed via the checks JSON (`clippedHeadings`/`tables`/`tinyText` counts are byte-identical light vs dark for every page) — so the table below cites light-theme evidence only.
- **Pages**: all 25 routes/states listed in the brief (morning, feed, item detail, entities list/detail/graph, investigations list/detail, ask, conferences, tenders, patents, payloads, inbox, reports list + monthly `?id=191` + weekly `?id=207`, bd, product-lines list/detail, dossiers list/detail/compare, tech-radar, settings), each with a viewport screenshot, a full-page screenshot, and a `page.evaluate` readability-check JSON. 100 test cases (25 screens × 2 themes × 2 engines) all passed; 356 files (screenshots + JSON) written to the scratchpad.
- **New files added to the repo** (kept for the lead to re-run after fixes):
  - `e2e/scripts/screens-iphone.spec.ts`
  - `e2e/scripts/pw.iphone-shots.config.ts`
  - Run with: `cd e2e && npx playwright test --config=scripts/pw.iphone-shots.config.ts --project=iphone-safari --project=mobile-390x844`
- **Evidence location** (not in the repo, per instructions): `C:\Users\cohyo\AppData\Local\Temp\claude\C--Users-cohyo-Documents-EO-analyst\3b24a26d-4bdd-49a3-b2dd-f67f85df545c\scratchpad\iphone-audit\`, files named `<nn>-<route>_<engine>_<theme>[-full][_<section>].png` and `..._checks.json`.
- **Methodology caveat (important)**: `AppShell.tsx` uses `h-dvh` with the real scroll container on `<main class="min-h-0 flex-1 overflow-y-auto">`, not `document.body`. Playwright's `fullPage` screenshot and a naive `document.documentElement.scrollWidth` overflow check both operate on the outer `<html>` box, which is pinned to viewport height — so (a) our "full-page" screenshots are pixel-identical to the viewport ones (verified: same byte size) and do **not** reveal content further down an inner-scrolling page, and (b) our horizontal-overflow check under-reports, because per the CSS overflow spec setting only `overflow-y` on an element implicitly computes `overflow-x` to `auto` too, so an over-wide child inside `<main>` scrolls locally instead of growing `document.documentElement.scrollWidth`. We compensated by manually scrolling to specific elements (dossier section anchors, report tables) and by reading `getComputedStyle`/`getBoundingClientRect` numbers from inside components directly (the `tables[]` array in each checks JSON is accurate regardless of this limitation). Two consequences worth flagging to the lead: (1) below-the-fold content on long pages (e.g. the entity graph canvas, which the code deliberately places *below* the list/card panes on mobile — see `EntitiesPage.tsx` comment at the `md:grid` block, a legitimate responsive choice, not a bug) was not visually re-verified; (2) some `<select>`/wide-child horizontal-overflow cases were only caught by eye, not by the automated check (see PATENTS/SETTINGS rows below).

## 3. Cross-cutting findings (fix once, repairs many pages)

- **TopBar H1 truncation (#2)** — affects all 25/25 pages; single highest-count finding. One fix in `TopBar.tsx` repairs every page's own heading at once.
- **NavRail's fixed 64px width (#4)** — affects all 25/25 pages; this is the structural reason nearly every table (#7), every filter `<select>` (#5), and the Feed row's headline (#1, compounded by its own badge cluster) are squeezed. Collapsing it to a bottom bar on `<md:` is the single highest-leverage fix in this whole audit.
- **Floating "Ask the analyst" pill (#8)** — affects all 25/25 pages, one `<main>` padding fix.
- **The `overflow-x-auto` + explicit `min-w` table pattern (#7)** is already correctly implemented in at least 8 separate components (`DossierTable`, `TenderTable`, `PatentTable`, `PayloadTable`, `RadarMatrix`, `ConferencesPage`, `InvestigationsListPage`, `SettingsPage`) — good news for the lead: none of these need individual changes, they all inherit the fix from #4.
- **Native `<select>` without `max-w-full` (#5)** — repeats verbatim in `PatentFilters.tsx` (×2) and `SettingsPage.tsx` (×1); worth a lint rule or a shared `<Select>` wrapper that always caps width.
